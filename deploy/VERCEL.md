# Qodex на Vercel

Qodex запускается как Python-функция, а постоянное хранилище рабочей базы находится в Neon. При первом входе создаётся пустая база со справочниками и учётной записью владельца. База локального Docker остаётся на компьютере, её перенос выполняется отдельно.

## Размещение

1. Для нового проекта откройте **Add New → Project** и импортируйте **emmustfan/qodex**. Если проект уже создан, откройте его и проверьте подключение репозитория в **Settings → Git**. Используйте корень репозитория и стандартные настройки сборки. Значение **Other** для Framework Preset уже задано в `vercel.json`. [Новый проект в Vercel](https://vercel.com/new)
2. Добавьте в переменные проекта для **Production** `QODEX_OWNER_PASSWORD` со своим паролем длиной от 12 символов. При желании добавьте `QODEX_OWNER_LOGIN`, иначе логин — `owner`. Пароль храните как чувствительную переменную Vercel. [Переменные окружения Vercel](https://vercel.com/docs/environment-variables)
3. В **Storage → Marketplace** подключите Neon к этому проекту для **Production**. Qodex использует добавленную интеграцией `DATABASE_URL` или `POSTGRES_URL`. Если вы подключаете уже существующую базу вручную, задайте `DATABASE_URL` со строкой подключения Neon с TLS. После подключения запустите **Redeploy** для production-развёртывания. [Интеграция Neon](https://vercel.com/marketplace/neon)
4. Откройте production-адрес из **Visit**. Введите логин и пароль владельца. В разделе **Сотрудники** создайте отдельные учётные записи и назначьте роли. Коллегам нужен production-адрес Qodex и их собственные учётные данные. Если у проекта включена отдельная защита Vercel для production, коллегам также понадобится разрешение этой защиты. [Защита развёртываний](https://vercel.com/docs/deployment-protection)

Для проверки создайте тестовую заявку под сотрудником, согласуйте её под владельцем и откройте снова после нового развёртывания. Для смены пароля после первого входа используйте раздел **Сотрудники**. Пароль из переменной применяется при создании первого владельца.

## Хранение

Python-функция хранит образ рабочей SQLite-базы в таблице `public.qodex_workspace` в Neon. При записи блокировка в PostgreSQL защищает изменения от параллельных запросов. Для пробных развёртываний используйте отдельную базу, чтобы изолировать данные от рабочих. Резервирование выполняется средствами Neon для выбранной базы.
