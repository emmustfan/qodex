# Qodex — финансовый прототип

Интерактивный прототип для трёх проектов, офиса и двух ООО. Приложение хранит данные в SQLite и открывается в браузере. Требуется Python 3.12 или Docker. Docker устанавливает зависимости автоматически. Для запуска без Docker установите пакеты из `requirements.txt`.

## Запуск демоверсии через Docker

Распакуйте архив, откройте терминал в папке `qodex` и выполните:

```bash
docker compose up --build -d
```

Откройте в браузере на этом же компьютере `http://127.0.0.1:8031`. Введите имя пользователя `demo` и пароль `qodex-demo`. Для проверки откройте июнь 2026. Данные сохраняются в отдельном томе Docker. Команда `docker compose down` останавливает приложение. Если порт занят, задайте `QODEX_DEMO_PORT` в файле `.env`, например `QODEX_DEMO_PORT=8032`, и откройте выбранный порт.

Этот Compose запускает демонстрацию с тестовыми данными и тестовым паролем на локальном интерфейсе. Для сотрудников используйте инструкции закрытого онлайн-пилота ниже.

## Локальная демонстрация

```bash
python -m pip install -r requirements.txt
python app.py
```

Откройте `http://127.0.0.1:8000`. В базе `data/finance.sqlite3` создаются синтетические операции и заявки. Июнь 2026 показывает заполненный пример.

1. Откройте «Операции» и распределите выплату дизайнеру в 120 000 ₽. Укажите −72 000 ₽ для «Ро-бота» и −48 000 ₽ для «Проекта 2». Для второго проекта можно выбрать другой месяц БДР.
2. Откройте «БДДС» и «БДР / P&L». Выберите месяц, проект и сценарий. Добавьте отдельную строку бюджета или ручное начисление.
3. Создайте заявку на расход и согласуйте её в разделе «Заявки». Проверьте статью и месяц оплаты в базовом плане БДДС.

Для импорта скачайте шаблон из формы. Поддерживается CSV UTF-8 с заголовками `id;date;description;amount`, датой `ГГГГ-ММ-ДД` и подписанной суммой в рублях. Перед загрузкой выберите конкретный банковский счёт. Повторы определяются отдельно по каждому счёту. Идентичные записи без ID считаются повтором, поэтому по возможности передавайте банковский ID. Ошибка в любой строке откатывает весь импорт. В прототипе входящий остаток компании или проекта задаётся вручную в обзоре и действует с начала выбранного дня.

## Два ООО и банковские счета

В разделе «Счета» есть по одному основному счёту у «ООО 1» и «ООО 2». Добавьте нужные счета и задайте входящие остатки на начало выбранного дня. Обзор показывает остаток выбранного счёта или сумму остатков по всем счетам выбранного ООО, если эти остатки заданы. План БДДС, начисления и заявки ведутся с указанием ООО. БДР доступен по ООО и по группе.

Для перевода загрузите обе выписки и выберите «Связать перевод» в операциях. Связать можно списание и поступление одинаковой суммы на разных счетах. Обе стороны остаются видимыми по счетам. При отчёте по ООО переводы между его счетами исключаются из оборота, а при отчёте по группе исключаются и переводы между ООО. При необходимости банковскую комиссию загрузите самостоятельной операцией.

При обновлении базы ранее импортированные операции сохраняются. У сохранённых операций без счёта можно выбрать счёт в реестре. Старые строки плана, начисления и заявки без ООО видны в общем отчёте. Для сверки истории сначала привяжите старые банковские операции, затем загружайте пересекающиеся выписки.

## Сверка выписок за месяц

1. В разделе «Счета» задайте входящий остаток на начало первого дня учёта для каждого счёта. Для сверки выбранного месяца нужна стартовая дата не позже первого дня этого месяца и все движения с этой даты.
2. Загрузите CSV по каждому счёту. Разнесите операции по статьям и проектам, включая офис, и свяжите встречные операции внутренних переводов.
3. В «Счетах» выберите месяц и откройте «Итоги выписки». Перенесите из банка остатки на начало и конец месяца, поступления и выплаты. Выплаты указываются положительной суммой.
4. Проверьте статус по каждому счёту. «Сверено» означает совпадение четырёх показателей. При расхождении показана разница «учёт минус банк» по каждому показателю. Сверка считает все движения счёта, включая внутренние переводы. Исключение переводов применяется в БДДС при объединении счетов или ООО.

## Закрытый онлайн-пилот

Опубликуйте приложение за HTTPS-прокси на выбранном сервере. Для пилота используйте отдельный том с пустой базой и отдельные учётные записи. В приватном файле `qodex.env` за пределами репозитория задайте `QODEX_USERS` как JSON в одной строке. Формат настройки с условными значениями:

```text
QODEX_USERS={"finance":{"password":"ПАРОЛЬ_ФИНАНСИСТА","role":"finance"},"employee":{"password":"ПАРОЛЬ_СОТРУДНИКА","role":"employee"}}
```

Замените условные значения уникальными случайными паролями. Ограничьте доступ к файлу правами владельца. На сервере выполните:

```bash
docker build -t qodex-prototype .
docker run -d --name qodex --restart unless-stopped \
  --env-file /защищённый/каталог/qodex.env \
  --mount source=qodex-data,target=/data \
  -p 127.0.0.1:8000:8000 qodex-prototype
```

Направьте HTTPS-прокси на `127.0.0.1:8000`. Контейнер создаёт чистую базу по умолчанию. Проверьте вход с обеими ролями, создание и согласование тестовой заявки и восстановление резервной копии тома. Для закрытого пилота используйте тестовые данные. Для работы с реальными выписками примените требования из ТЗ по доступу, резервному копированию и сверке.

## План разработки и оплата заявок

См. [план разработки](ПЛАН.md) и критерии приёмки по этапам.

Для проверки полного цикла создайте заявку на расход одного ООО и согласуйте её. В реальном режиме решение принимает другой пользователь с ролью финансиста. Загрузите банковское списание на счёт этого ООО. Откройте «Оплаты» в заявке и выберите списание. Для частичной оплаты сумма списания должна быть меньше остатка заявки. В «Платёжном календаре» будут видны оставшаяся сумма, срок и возможность перенести оплату. Исходный месяц в базовом БДДС сохраняется для сравнения с фактом.


«Прогноз денег» рассчитывает остаток по датам на основе банковского факта, неоплаченных заявок и ручных ожидаемых движений. Выберите ООО и месяц горизонта. Для денежного остатка задайте входящие остатки по всем его счетам. После прихода или списания денег удалите соответствующую ручную строку, чтобы не учитывать движение дважды. Просроченные ожидания и неоплаченные остатки в расчёте считаются движением на сегодня.

Нажмите «Зафиксировать план» в БДДС или БДР, чтобы сохранить именованную версию плана на выбранный месяц и сценарий по всем ООО. Выберите её в списке версий для сравнения с актуальным фактом. Текущий план можно продолжать пополнять независимо от сохранённой версии.


## Импорт сценариев «Ро-бота»

Откройте **БДДС → Импорт модели «Ро-бот»**, выберите ООО и загрузите рассчитанную книгу XLSX с листами «Сценарий 50», «Сценарий 75» и «Сценарий 100». Для каждого сценария покажутся поступления и выплаты с ноября 2026 по декабрь 2027. Проверьте суммы и нажмите «Импортировать в БДДС».

Сценарий 50 становится консервативным, 75 — базовым, 100 — оптимистичным. Строки оплат лицензий суммируются в поступления. Операционные расходы отражаются в предусмотренном моделью месяце, поэтому проверьте сроки выплат перед использованием плана. Возврат вложений и дивиденды добавляются отдельными статьями по выбору. Исторический факт, фонд развития и БДР из книги не загружаются. График начисления выручки для БДР составляется отдельно.

При повторной загрузке заменяются ранее импортированные строки того же ООО. Ручные строки и сохранённые версии бюджета сохраняются. Строки модели складываются с ручным планом и согласованными заявками, поэтому при сверке проверьте пересечения. Приложение использует сохранённые значения формул. После правок пересчитайте книгу в Excel и сохраните её перед импортом.
