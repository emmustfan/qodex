# Qodex — финансовый прототип

Интерактивный прототип для трёх проектов, офиса и двух ООО. Приложение хранит данные в SQLite и открывается в браузере. Требуется Python 3.12 или Docker. Docker устанавливает зависимости автоматически. Для запуска без Docker установите пакеты из `requirements.txt`.

## Запуск демоверсии через Docker

Распакуйте архив, откройте терминал в папке `qodex` и выполните:

```bash
docker compose up --build -d
```

Откройте в браузере на этом же компьютере `http://127.0.0.1:8031`. Введите имя пользователя `demo` и пароль `qodex-demo`. Для проверки откройте июнь 2026. Данные сохраняются в отдельном томе Docker. Команда `docker compose down` останавливает приложение. Если порт занят, задайте `QODEX_DEMO_PORT` в файле `.env`, например `QODEX_DEMO_PORT=8032`, и откройте выбранный порт.

Этот Compose запускает демонстрацию с тестовыми данными и тестовым паролем на локальном интерфейсе. Для сотрудников используйте инструкции закрытого онлайн-пилота ниже.

Для запуска в браузере без локального компьютера доступны [Vercel и постоянная база Neon](deploy/VERCEL.md).

## Локальная демонстрация

```bash
python -m pip install -r requirements.txt
python app.py
```

Откройте `http://127.0.0.1:8000`. В базе `data/finance.sqlite3` создаются синтетические операции и заявки. Июнь 2026 показывает заполненный пример.

1. Откройте «Операции» и распределите выплату дизайнеру в 120 000 ₽. Укажите −72 000 ₽ для «Ро-бота» и −48 000 ₽ для «Проекта 2». Для второго проекта можно выбрать другой месяц БДР.
2. Откройте «БДДС» и «БДР / P&L». Выберите месяц, проект и сценарий. Добавьте отдельную строку бюджета или ручное начисление.
3. Создайте заявку на расход и согласуйте её в разделе «Заявки». Проверьте статью и месяц оплаты в базовом плане БДДС.

Для импорта скачайте шаблон из формы. Поддерживается CSV UTF-8 с заголовками `id;date;description;amount`, датой `ГГГГ-ММ-ДД` и подписанной суммой в рублях. Перед загрузкой выберите конкретный банковский счёт. Повторы определяются отдельно по каждому счёту. Идентичные записи без ID считаются повтором, поэтому по возможности передавайте банковский ID. Ошибка в любой строке откатывает весь импорт. В прототипе входящий остаток компании или проекта задаётся вручную в обзоре и действует с начала выбранного дня.

## Два ООО и банковские счета

В разделе «Счета» есть по одному основному счёту у «ООО 1» и «ООО 2». Добавьте нужные счета и задайте входящие остатки на начало выбранного дня. Обзор показывает остаток выбранного счёта или сумму остатков по всем счетам выбранного ООО, если эти остатки заданы. План БДДС, начисления и заявки ведутся с указанием ООО. БДР доступен по ООО и по группе.

Для перевода загрузите обе выписки и выберите «Связать перевод» в операциях. Связать можно списание и поступление одинаковой суммы на разных счетах. Обе стороны остаются видимыми по счетам. При отчёте по ООО переводы между его счетами исключаются из оборота, а при отчёте по группе исключаются и переводы между ООО. При необходимости банковскую комиссию загрузите самостоятельной операцией.

При обновлении базы ранее импортированные операции сохраняются. У сохранённых операций без счёта можно выбрать счёт в реестре. Старые строки плана, начисления и заявки без ООО видны в общем отчёте. Для сверки истории сначала привяжите старые банковские операции, затем загружайте пересекающиеся выписки.

## Сверка выписок за месяц

1. В разделе «Счета» задайте входящий остаток на начало первого дня учёта для каждого счёта. Для сверки выбранного месяца нужна стартовая дата не позже первого дня этого месяца и все движения с этой даты.
2. Загрузите CSV по каждому счёту. Разнесите операции по статьям и проектам, включая офис, и свяжите встречные операции внутренних переводов.
3. В «Счетах» выберите месяц и откройте «Итоги выписки». Перенесите из банка остатки на начало и конец месяца, поступления и выплаты. Выплаты указываются положительной суммой.
4. Проверьте статус по каждому счёту. «Сверено» означает совпадение четырёх показателей. При расхождении показана разница «учёт минус банк» по каждому показателю. Сверка считает все движения счёта, включая внутренние переводы. Исключение переводов применяется в БДДС при объединении счетов или ООО.

## Закрытый онлайн-пилот

Опубликуйте приложение за HTTPS-прокси на выбранном сервере. Для пилота используйте отдельный том с пустой базой и отдельные учётные записи. В приватном файле `qodex.env` за пределами репозитория задайте `QODEX_USERS` как JSON в одной строке. Формат настройки с условными значениями:

```text
QODEX_USERS={"finance":{"password":"ПАРОЛЬ_ФИНАНСИСТА","role":"finance"},"employee":{"password":"ПАРОЛЬ_СОТРУДНИКА","role":"employee"}}
```

Замените условные значения уникальными случайными паролями. Ограничьте доступ к файлу правами владельца. На сервере выполните:

```bash
docker build -t qodex-prototype .
docker run -d --name qodex --restart unless-stopped \
  --env-file /защищённый/каталог/qodex.env \
  --mount source=qodex-data,target=/data \
  -p 127.0.0.1:8000:8000 qodex-prototype
```

Направьте HTTPS-прокси на `127.0.0.1:8000`. Контейнер создаёт чистую базу по умолчанию. Проверьте вход с обеими ролями, создание и согласование тестовой заявки и восстановление резервной копии тома. Для закрытого пилота используйте тестовые данные. Для работы с реальными выписками примените требования из ТЗ по доступу, резервному копированию и сверке.

## План разработки и оплата заявок

См. [план разработки](ПЛАН.md) и критерии приёмки по этапам.

Для проверки полного цикла создайте заявку на расход одного ООО и согласуйте её. В реальном режиме решение принимает другой пользователь с ролью финансиста. Загрузите банковское списание на счёт этого ООО. Откройте «Оплаты» в заявке и выберите списание. Для частичной оплаты сумма списания должна быть меньше остатка заявки. В «Платёжном календаре» будут видны оставшаяся сумма, срок и возможность перенести оплату. Исходный месяц в базовом БДДС сохраняется для сравнения с фактом.


«Прогноз денег» рассчитывает остаток по датам на основе банковского факта, неоплаченных заявок и ручных ожидаемых движений. Выберите ООО и месяц горизонта. Для денежного остатка задайте входящие остатки по всем его счетам. После прихода или списания денег удалите соответствующую ручную строку, чтобы не учитывать движение дважды. Просроченные ожидания и неоплаченные остатки в расчёте считаются движением на сегодня.

Нажмите «Зафиксировать план» в БДДС или БДР, чтобы сохранить именованную версию плана на выбранный месяц и сценарий по всем ООО. Выберите её в списке версий для сравнения с актуальным фактом. Текущий план можно продолжать пополнять независимо от сохранённой версии.


## Рабочий месяц

Владелец и финансист открывают месяц по одному ООО. Дата среза и кнопки концов недель ограничивают банковские поступления, выплаты и расчёт премий. БДР показывает текущие начисления за весь месяц. Фильтр проекта уточняет разнесённые движения, бюджет, правила и действия. Остатки банков и фондов показываются по всему выбранному ООО.

- **Деньги.** Задайте входящие остатки по счетам, загрузите выписку и разнесите операции. В прогноз входят ожидаемые движения, неоплаченные остатки согласованных заявок, подтверждённые премии вне заявок и запланированные изменения резервов. После оплаты отметьте ручное движение исполненным. При разрыве проверьте фонды этого ООО и при необходимости оформите высвобождение резерва.
- **Правила.** Для техподдержки выберите фиксированный плановый расход за месяц. Для продаж выберите процент от положительных операционных поступлений по проекту и при необходимости ограничьте его одной статьёй поступлений. План премии считается от бюджета поступлений БДДС выбранного сценария. Нажмите «Внести в план», чтобы перенести результат в текущий БДР. Изменения правил действуют с выбранного открытого месяца. Ручная строка бюджета по той же статье имеет приоритет.
- **Премии.** Выберите отдельную статью расхода и используйте её при разнесении выплат. После проверки подтвердите начисление. БДР добавит разницу между рассчитанной суммой и начислениями по этой статье, которые уже есть в учёте. Подтверждение относится ко всей премии проекта за месяц. Сумму можно обновить по мере поступлений до закрытия. Когда банк проведёт сам платёж, выберите «Оплата премии за месяц» в разнесении списания. Это погасит остаток по премии и сохранит закрытый БДР. Выплаты прошлых месяцев видны под расчётом по правилам.
- **Действия.** Добавьте задачу на следующий созвон, срок и ответственного. Открытая задача видна и в следующих месяцах. Для ожидаемого платежа с суммой и датой используйте «Ожидаемое движение». В конце месяца запустите проверку закрытия, включая проверку премий.

## Выписка Точки и разнесение

1. Откройте **Операции → Импорт выписки** и выберите файл XLSX из Точки. В выписке нужны листы «Операции» и «Выписка».
2. Выберите вариант «Счёт Точки» под нужным ООО. Номер берётся из файла, при первой загрузке создаётся отдельный счёт. При повторных загрузках тот же номер направляется на уже созданный счёт. Выберите существующий счёт вручную, если хотите привязать выгрузку к нему. Сравните даты и четыре банковских итога в предпросмотре.
3. Нажмите «Загрузить операции». Система сравнивает обороты с выпиской, пропускает повторы XLSX и показывает итог за загруженный период в разделе «Счета». CSV и XLSX используют разные идентификаторы, поэтому сверяйте пересечения файлов разных форматов вручную.
4. В операциях проверьте предложения по статье и проекту. Кнопка «Подсказки» позволяет подтвердить за месяц строки с обеими аналитиками. Для остальных операций выберите проект или офис и статью вручную. Платёж можно разбить между проектами. При разнесении одной строкой можно запомнить проект и статью этого контрагента для будущих подсказок по данному счёту и направлению.
5. Для аванса без акта поставьте «Ждём акт или другой документ». Платёж будет в БДДС. После получения документа снимите отметку и укажите месяц БДР, если начисление ещё не было записано вручную. Открытые случаи можно найти фильтром «Ждём документы».

Чтобы распределить несколько платежей, отфильтруйте поступления или расходы. При необходимости уточните выборку поиском по назначению, контрагенту или клиенту. Отметьте нужные строки или поставьте галочку в шапке таблицы для всех видимых доступных операций. Нажмите **Распределить выбранные** и укажите общий проект и статью БДДС. Для уже распределённых платежей подтвердите замену. Оставьте месяц БДР пустым, чтобы сохранить существующие месяцы и статьи начислений. Можно указать общий месяц и статью БДР для всей группы, если по всем операциям есть документы. Связанные операции и платежи закрытых периодов недоступны для массового распределения.

Пометки о возможных депозитах и переводах служат для проверки. Встречные банковские операции связываются через «Связать перевод». Внутреннее резервирование и решения по прибыли ведутся в отдельных разделах. Файл банковской выписки не хранится целиком, в базе сохраняются операции и итоги диапазона дат.


## Фонды, офис и прибыль

- **Фонды.** Создайте фонд у нужного ООО. Через «Движение» запишите пополнение или высвобождение резерва с датой и основанием. Отчёт показывает начальный и конечный остатки, обороты за месяц и журнал. Свободные деньги рассчитываются как банковский остаток за вычетом резервов, если заданы входящие остатки по всем счетам выбранного ООО или группы. Результат может быть отрицательным, например при резервировании суммы выше текущей ликвидности.
- **Вклад проектов в офис.** В разделе «Распределение прибыли» укажите сумму вклада проекта за выбранный месяц. Проектный результат уменьшается на эту сумму, а результат офиса увеличивается. Общий результат ООО и деньги на счетах сохраняются. Офисные расходы появляются в отчёте после разнесения и начисления на центр «Офис».
- **Решения.** Запишите решения по прибыли за месяц. Отчисление в фонд создаёт запись о резерве на дату решения. Для собственника можно указать получателя в основании и сохранить отдельное решение. Таблица показывает остаток после решений и предупреждает, если решения превышают результат. При отмене сохраняется история, а отменить отчисление в фонд можно, если после отмены фонд не уйдёт в минус.
- **Оплаты.** Управленческие записи не создают банковских операций и не меняют БДДС или БДР. Фактическая выплата собственникам приходит из банковской выписки. В разделе «Распределение прибыли» откройте «Выплаты» у решения и привяжите списание со счёта того же ООО. Можно привязать несколько частичных оплат. Одно списание целиком относится к одному решению. После привязки в БДДС сумма видна по статье «Дивиденды» и по дате банка. В решении видны выплаченная сумма и остаток. При снятии связи банк и прежнее разнесение сохраняются. Для использования средств фонда отдельно запишите высвобождение.


## Проекты, статьи и клиенты

В разделе **«Справочники»** можно добавить проект, статью поступления или расхода и основного клиента. Проекты доступны в операциях, планах, начислениях, заявках и фильтрах отчётов. «Офис» используется для общекорпоративных расходов.

В **«Операциях»** выберите поступления или расходы и откройте разнесение. Статьи соответствуют знаку суммы. Для денежного факта используйте «Аванс от клиента», «Промежуточный платёж» и «Окончательный расчёт». Чтобы заработанная выручка появилась в P&L, укажите месяц и при необходимости статью БДР, например «Внедрение». Без месяца оплата остаётся в денежном факте. Если доход начислен отдельной записью, месяц БДР в операции оставьте пустым.

У выписки Точки имя плательщика берётся из банковской колонки «Контрагент». При импорте CSV можно передать дополнительную колонку `counterparty`. Для операции без имени плательщика его можно указать вручную. В карточке поступления выберите или создайте основного клиента. Поступления от нескольких юрлиц можно связать с одним клиентом. Для банковского плательщика можно сохранить правило подсказки. Оно использует банковские идентификаторы плательщика и применяется к будущим предложениям. Историю уже размеченных поступлений можно проверить в справочнике клиентов.


## Дерево статей и БДР

В **«Справочники» → «Дерево статей»** добавляйте группы и подгруппы. В настройках статьи выберите группу, проект по умолчанию и разделы БДР для проектов и офиса. Например, добавьте «Зарплата разработчика Ро-бота» в группу «Зарплата», выберите проект «Ро-бот» и раздел прямых расходов. Проект подставится при выборе статьи, если поле проекта пустое. При разнесении можно явно выбрать другой проект.

В панели **«Разделы БДР»** добавляйте и переименовывайте разделы внутри уровней отчёта. В БДР доходы за вычетом расходов проекта дают его скорректированный доход. Результат офиса формирует следующий итог — маржинальную прибыль. Премии, маркетинг и развитие можно отнести в отдельные разделы после неё. Решения о дивидендах показаны после операционного результата. Фактические выплаты собственникам видны в БДДС.

В **БДР** и **БДДС** выберите «Группа статей», чтобы увидеть суммы по группе и всем её подгруппам. Выберите «Все проекты» для общей суммы, например по зарплате. БДР показывает начисления по статье БДР, БДДС показывает платежи по статье разнесения. Раскрывайте строки дерева и нажимайте суммы для расшифровки. Excel выгружает выбранный разрез со всеми строками дерева. Группы и разделы применяются к историческим месяцам по текущим настройкам.


## Графики начислений

Откройте **«Графики начислений» → «+ График»**. Выберите ООО, проект, статью БДР, первый месяц, срок и общую сумму договора. В предпросмотре сумма делится поровну по календарным месяцам с точностью до копейки. Первые месяцы получают остаток округления. Сохранённый график находится к подтверждению. Подтвердите строку за месяц на основании договора, акта или расчёта. Только подтверждённая строка входит в факт P&L. Подтверждение можно снять, чтобы исправить ошибку.

В «Оплатах» привяжите банковские операции. Каждое списание или поступление используется целиком и должно быть разнесено на проект того же ООО с пустым месяцем БДР. У графика видны сумма связанных оплат и остаток. Сумма и дата фактического движения денег сохраняются в БДДС. В графике учитываются только связанные операции. Если выручка или расход уже внесены ручным начислением за этот месяц, используйте одну запись факта.


## Распределение расходов офиса

В разделе **«Распределение прибыли» → «Распределить офис»** выберите ООО и базу. По выручке используется признанная в БДР выручка проектов за выбранный месяц. В ручном режиме можно задать веса, например 60 и 40. Qodex распределяет фактически начисленные расходы центра «Офис» с точностью до копейки.

Предпросмотр сравнивает текущий и новый вклад. При применении распределение заменяет вклады выбранного ООО за месяц после подтверждения. Вклад переносит сумму с проектов на офис в отчёте о прибыли, поэтому общий результат ООО сохраняется. Если начисления изменились после расчёта, обновите предпросмотр. Для отдельной ручной корректировки используйте «Вклад в офис».

## Проверка и корпоративный пилот

[Сценарий сквозной приёмки](ПРОВЕРКА.md) содержит тестовые роли и ожидаемые результаты. [Инструкция защищённого запуска](deploy/README.md) описывает HTTPS, корпоративный вход и восстановление базы.

Проекты и статьи с историей можно архивировать и восстанавливать, а неиспользованные удалять. Данные архива остаются в отчётах. Управление сотрудниками доступно владельцу. Для руководителя «Мои проекты» открывает результаты, строки бюджета и датированный график назначенных проектов.

## Продуктовый БДР и БДДС с ноября 2026

В **«Справочники» → «Установить структуру продуктов»** владелец или финансист один раз добавляет готовые проекты, группы и статьи и открывает БДР за ноябрь. Ро-бот сворачивает Жильё, ГИС ЖКХ и Коммерцию. Кодекс TONN сворачивает Signal и Gravity. ТКО и Tracker считаются самостоятельно. Для общих расходов используйте родительский продукт. В отчёте они будут видны отдельно от модулей и войдут в итог продукта.

Загрузите ноябрьские выписки по счетам. Если по счёту ещё не задан входящий остаток, внесите остаток на 1 ноября в разделе «Счета». В БДДС выбирайте ноябрь для сверки по датам платежей. В БДР указывайте ноябрь для доходов и расходов, относящихся к этому месяцу. Например, оплата ноябрьской услуги в декабре относится к БДР ноября и БДДС декабря.

- Выручка от лицензии, оборудования, монтажа, внедрения, техподдержки и перепродажи данных учитывается отдельными статьями. Указывайте номер заказа или документа 1С в описании, чтобы найти соответствующую смету и акт. Факт по оборудованию и монтажу относите на месяц передачи и приёмки. Предоплата поставщику до передачи остаётся в денежном учёте.
- Маржа покрытия равна выручке за вычетом затрат из раздела «Переменные затраты проектов». После ФОТ и прочих затрат продукта получается его скорректированный доход. Аутсорс-бухгалтерия, распределённая между проектами, учитывается в общих услугах проекта. Доля без проектной привязки остаётся в офисе.
- В карточке списания выберите статью и месяц БДР, затем **«Распределить по часам или операциям»**. Для ФОТ введите часы одного сотрудника за период, для бухгалтерии — число обработанных операций по каждому проекту за этот же период. Используйте одинаковый способ подсчёта для всех проектов. Нажмите **«Рассчитать доли»**, проверьте суммы и сохраните. Основание расчёта будет в журнале.
- Для премий с оплат и с маржи оборудования предусмотрены две статьи. Премию с маржи рассчитывайте по себестоимости конкретного заказа и утверждённой ставке, затем вносите подтверждённое начисление. Для комплектов сначала согласуйте смету с разбивкой по позициям.
